# Lightweight Governance and Official Operations

Author: PaperProof Labs  
Category: Governance  

This starter topic is for governance and operations discussion before formal
votes or parameter changes are created.

PaperProof uses governance-aware objects to separate official protocol state
from arbitrary writes. The core protocol includes deployment bindings,
governance vaults, fee-related objects, proposal flows, and operational
controls. Additional registries, such as native prompts and Agent Memory
capabilities, follow a lighter management pattern while still respecting
official authority boundaries.

Not every operational decision needs a heavy proposal-and-execute workflow.
Some official interface choices, manifest updates, prompt route updates, memory
availability decisions, and content curation decisions may be better handled as
lightweight official operations, documented clearly and reflected in the
relevant registry or manifest.

Useful questions for this board include:

- Which changes should require formal voting?
- Which changes should be handled by an official operator path?
- How should PaperProof communicate public launch timing and pre-launch setup
  activity?
- What should be the policy for disabling official prompt or memory
  capabilities?
- How should fees and sustainability parameters be discussed before proposals?

Discussion here is not itself a vote. It is a place to refine reasoning,
collect objections, and prepare better formal actions when formal actions are
needed.
