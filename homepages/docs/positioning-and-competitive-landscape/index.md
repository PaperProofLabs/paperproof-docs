PaperProof is easiest to misunderstand when it is compared to a single content
app. It is not only a blog, a forum, a preprint server, or a software release
page. It is a protocol-native artifact layer designed to give high-value
digital works a stable, verifiable, versioned identity across human and agent
workflows.

The official website demonstrates one way to use the protocol. The broader
claim is deeper: papers, reports, datasets, software releases, official docs,
discussion trees, prompts, and governed memory metadata can all be treated as
first-class protocol objects instead of disconnected platform records.

## Why this section exists

PaperProof sits between several familiar categories:

- onchain publishing;
- open social protocols;
- research and archival infrastructure;
- software and dataset release systems;
- agent-readable knowledge coordination.

Because it sits across categories, it is useful to explain the protocol through
ecosystem position, competitive overlap, and structural advantages rather than
through a single simplistic comparison.

## What to keep in mind

PaperProof is centered on the artifact, not the feed.

That means the protocol treats the continuing work as the primary object:

- a stable series identity;
- append-only versions;
- content hash commitments;
- Walrus blob references;
- official comments and likes bindings;
- indexer and SDK readability;
- governed official registries where needed.

This gives the protocol a different center of gravity from systems optimized
for posts, follows, timelines, and recommendation loops.
